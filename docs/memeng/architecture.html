memeng Architecture

Two Claude Code hooks drive the memory system. The UserPromptSubmit hook recalls facts before Claude reads your message. The Stop hook remembers new facts after each reply. Both share one SQLite file.

Recall UserPromptSubmit hook, before each message

  1. Claude Code sends your message to the UserPromptSubmit hook. The hook calls search() in the same process.
  2. Ollama embeds the message into one vector.
  3. knn over memories_vec returns candidates with cosine ≥ 0.5. BM25 over memories_fts and matches in entities score the same candidates.
  4. scoring.py fuses the three scores and keeps the top 10.
  5. Conflicting and superseded facts are flagged. Facts already shown this session are dropped.
  6. The hook returns the memories as additionalContext. A detached process writes the retrieval to logs_* and injections.

Remember Stop hook, after each reply

  1. Claude Code fires the Stop hook. The hook starts a detached capture process and returns at once.
  2. Capture reads new turns from the transcript and inserts them into messages. It claims all unprocessed turns as one window.
  3. The Claude CLI answers the gate prompt: does the window hold anything worth saving? A "no" stops the capture.
  4. Capture embeds the window and fetches similar stored facts by knn. The Claude CLI extracts facts, entities, and any older fact each one supersedes.
  5. Facts whose md5 hash already exists are dropped. Ollama embeds the rest. Each fact goes into memories, memories_vec, memories_fts, entities and supersession.
